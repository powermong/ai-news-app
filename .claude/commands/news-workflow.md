뉴스 수집기 앱의 새 기능 개발 워크플로우를 아래 단계대로 순서를 지켜 진행한다.
브랜치 이름: `$ARGUMENTS`

## 1단계: 현재 상태 확인

- `git branch --show-current`와 `git status --short`로 현재 브랜치와 작업 트리 상태를 확인한다.
- main 브랜치가 아니면 현재 브랜치 이름을 알리며 경고하고, main으로 이동할지 사용자에게 묻는다. 사용자가 동의하기 전에는 다음 단계로 진행하지 않는다.
  - 동의하면 `git checkout main`으로 이동한다. 커밋되지 않은 변경 때문에 이동이 실패하면 상황을 설명하고 사용자 판단을 기다린다(임의로 stash/버리기 금지).
  - 거절하면 워크플로우를 중단한다.
- main이라면 작업 트리가 깨끗한지도 함께 알려 준다.

## 2단계: 새 브랜치 생성

- `$ARGUMENTS`가 비어 있지 않으면 그 이름으로 `git checkout -b <이름>`을 실행한다.
- `$ARGUMENTS`가 비어 있으면 어떤 기능을 개발할 것인지 사용자에게 묻고, 답변을 바탕으로 **영어 소문자-하이픈** 형식의 브랜치 이름(예: `article-search`, `category-sort`)을 제안한다. 사용자가 확인하거나 수정한 이름으로 브랜치를 만든다.
- 이미 같은 이름의 브랜치가 있으면 덮어쓰지 말고 사용자에게 알린다.

## 3단계: 개발 시작 안내

- 브랜치 생성이 끝나면 **"이제 개발을 시작하세요!"** 라고 안내한다.
- `CLAUDE.md`를 읽고 이 프로젝트의 기술 스택과 컨벤션을 다시 한번 알려 준다. 최소한 다음을 포함한다.
  - 스택: Next.js(App Router, 16.x/React 19), Tailwind 4, Clerk 인증, Neon Postgres + Drizzle ORM, Claude API, rss-parser, Notion REST API
  - 모든 페이지/`/api/*`는 Clerk 인증 필수, 모든 쿼리는 Clerk `userId`로 범위 제한
  - 요구사항은 `PRD.md`, UI는 `ui.md`를 먼저 읽을 것
  - Next.js 코드를 쓰기 전에 `node_modules/next/dist/docs/`의 관련 가이드를 읽을 것(`AGENTS.md` 참고)
  - 비밀 키는 서버 측 환경 변수로만 사용
  - 테스트 러너는 없고, 검증은 `npm run lint` / `npm run build`
- 그 후 사용자의 개발 요청을 기다리며, 요청에 따라 개발을 돕는다.

## 4단계: 완료 처리

사용자가 **"완료"** 또는 **"done"** 이라고 입력하면:

1. `git status --short`와 `git diff --stat`으로 변경된 파일 목록을 보여 준다(새 파일 포함).
2. 변경 내용을 바탕으로 이 저장소의 기존 커밋 메시지 스타일(`git log --oneline`, 한국어 한 줄 요약)에 맞춰 커밋 메시지를 제안한다.
3. 사용자가 확인(또는 수정)하면:
   - 변경 파일을 명시적으로 `git add` 하고(`.env*` 등 비밀 파일은 제외), 커밋한다.
   - `git checkout main` 후 `git merge <브랜치>`로 병합한다.
   - 병합 충돌이 나면 멈추고 충돌 파일을 알린 뒤 사용자 판단을 기다린다.
4. 사용자가 확인하지 않으면 커밋하지 않는다.
5. push, 브랜치 삭제는 사용자가 요청하기 전에는 하지 않는다.

## 5단계: 작업 요약

병합이 끝나면 다음을 요약해서 보여 준다.

- 브랜치 이름과 병합 결과(커밋 해시, 메시지)
- 변경된 파일 목록과 각 파일의 변경 요지
- 구현한 기능의 핵심 내용
- 후속 작업 제안(예: CLAUDE.md의 Status 갱신 필요 여부, push 여부, 브랜치 삭제 여부)
